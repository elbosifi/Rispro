# Patient QR Settings Not Saving/Reflecting - Bug Fix Plan

## Root Cause

The `fetchPatientQrSettings()` function in `frontend/src/lib/api-hooks.ts:512-514` incorrectly parses the API response.

**The Bug:**
- `fetchPatientQrSettings()` calls `GET /settings/patient_qr_self_service`
- Backend returns `{ settings: [{ setting_key, setting_value }, ...] }`
- But the function passes the entire response object to `normalizePatientQrSettings()` instead of extracting the "config" row first

**Code Issue (api-hooks.ts:512-514):**
```typescript
export async function fetchPatientQrSettings(): Promise<PatientQrSettings> {
  const raw = await api<RawRecord>("/settings/patient_qr_self_service");
  return normalizePatientQrSettings(raw);  // BUG: 'raw' is { settings: [...] }, not a settings row
}
```

The `normalizePatientQrSettings()` function expects a single settings row with `setting_value` property, but receives the entire API response object.

## Impact

1. **Settings page always shows defaults** - When loading the settings page, it shows default values instead of saved values
2. **Risk of data loss** - If user opens settings page and saves without changing values, it may overwrite actual saved settings with defaults

## Fix

**File to modify:** `frontend/src/lib/api-hooks.ts`

**Current code (lines 512-514):**
```typescript
export async function fetchPatientQrSettings(): Promise<PatientQrSettings> {
  const raw = await api<RawRecord>("/settings/patient_qr_self_service");
  return normalizePatientQrSettings(raw);
}
```

**Fixed code:**
```typescript
export async function fetchPatientQrSettings(): Promise<PatientQrSettings> {
  const response = await api<{ settings: RawRecord[] }>("/settings/patient_qr_self_service");
  const configRow = response.settings?.find((row) => row.setting_key === "config");
  return normalizePatientQrSettings(configRow ?? {});
}
```

2. Change a setting (e.g., toggle `allowCancellation`)
3. Save the settings
4. Refresh the page - the changed setting should persist
5. Test the cancellation page with a valid token - the `allowCancellation` setting should be reflected correctly
