# Plan: Deprecate and Remove Legacy Appointment Form

## Context

The codebase has two appointment systems:
- **Legacy system**: `appointment-service.ts` (3193 lines), `routes/appointments.ts`, `frontend/src/pages/appointments/appointments-page.tsx`
- **V2 system**: `modules/appointments-v2/`, V3 frontend page (`create-appointment-v3-page.tsx`)

The App.tsx already routes `/appointments` to V3 page, and `/appointments/legacy` redirects to `/appointments`. The legacy form is no longer directly accessible.

## Files to Remove

### Phase 1: Frontend Legacy Page
1. **Delete** `frontend/src/pages/appointments/appointments-page.tsx` (1219 lines - legacy form)
2. **Delete** `frontend/src/pages/appointments/appointments-page.readiness.test.ts`

### Phase 2: Backend Legacy Routes
3. **Delete** `src/routes/appointments.ts` (201 lines - legacy API routes)

### Phase 3: Refactor appointment-service.ts

The `appointment-service.ts` is still used by:
- `src/routes/settings.ts` - imports exam type & modality CRUD functions
- `src/services/queue-service.ts` - imports `createAppointment` function
- Various test files

#### 3a: Extract Exam/Modality Management Functions

Create new file `src/services/catalog-service.ts` with functions currently in `appointment-service.ts`:
- `createExamType`
- `updateExamType`
- `deleteExamType`
- `hardDeleteExamType`
- `listExamTypesForSettings`
- `createModality`
- `updateModality`
- `deactivateModality`
- `hardDeleteModality`
- `listModalitiesForSettings`

#### 3b: Update Dependencies

1. **Update** `src/routes/settings.ts`:
   - Change imports from `appointment-service.ts` to `catalog-service.ts`

2. **Update** `src/services/queue-service.ts`:
   - Replace `createAppointment` from legacy service with `createBooking` from `modules/appointments-v2/booking/services/create-booking.service.ts`
   - May need to add a wrapper function to adapt the payload format

#### 3c: Delete Legacy Functions from appointment-service.ts

Remove these functions (used only by legacy routes being deleted):
- `getAppointmentDaySettings`
- `getAppointmentPrintDetails`
- `listAppointmentStatistics`
- `listAppointmentsForPrint`
- `listAvailability`
- `listSuggestedAppointments`
- `createAppointment`
- `updateAppointment`
- `updateAppointmentProtocol`
- `cancelAppointment`
- `deleteAppointment`
- `toSchedulingConflictError`
- `overrideOutcomeForFailure`

#### 3d: Clean Up Remaining appointment-service.ts

After extraction, the remaining functions in `appointment-service.ts` would be the catalog functions. At this point, either:
- Rename `appointment-service.ts` to `catalog-service.ts` (if keeping the file)
- Or delete `appointment-service.ts` entirely (if all functions moved to new service)

### Phase 4: Update Frontend API Hooks

**Update** `frontend/src/lib/api-hooks.ts`:
1. Remove `createAppointment` function (lines 333-339) - no longer needed if legacy routes deleted
2. Update `updateAppointment` (lines 398-417) - remove legacy fallback
3. Update `cancelAppointment` (lines 419-435) - remove legacy fallback
4. Update `deleteAppointment` (lines 437-452) - remove legacy fallback
5. Remove `updateAppointmentProtocol` (lines 454-460) if no V2 equivalent exists

### Phase 5: Delete Test Files

Delete legacy test files:
- `src/services/appointment-service.integration.test.ts`
- `src/services/appointment-service.exam-type-delete.test.ts`
- `src/services/appointment-service.modality-delete.test.ts`
- `src/services/appointment-service.availability.test.ts`
- `src/services/appointment-service.hardening.test.ts`

Keep tests related to extracted catalog functions (may need to update imports).

## Files to Keep (Not Legacy)

- `frontend/src/components/appointments/appointment-editor.tsx` - Still used by registrations, modality, doctor, and calendar pages. Already uses V2 exam types.
- `src/modules/appointments-v2/` - Active V2 system
- `frontend/src/v2/appointments/` - Active V2 frontend

## Verification Steps

1. Run TypeScript type checking: `npm run typecheck` (or equivalent)
2. Run tests: `npm test`
3. Verify the app loads and:
   - `/appointments` shows V3 create page
   - Registrations page can still edit appointments (uses appointment-editor)
   - Settings page can still manage exam types and modalities
   - Queue service can still create walk-in appointments

## Rollback Plan

If issues arise:
1. The deleted files can be restored from git history
2. Keep the legacy routes but add a deprecation notice/redirect
3. Temporarily keep appointment-service.ts with deprecated flags

## Order of Implementation

1. Phase 1: Delete frontend legacy page (low risk - already inaccessible)
2. Phase 3a & 3b: Extract and update dependencies (medium risk - need careful testing)
3. Phase 2: Delete backend legacy routes (after dependencies updated)
4. Phase 3c & 3d: Clean up appointment-service.ts
5. Phase 4: Update frontend API hooks
6. Phase 5: Delete test files
7. Final verification
